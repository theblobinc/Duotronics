# Release Notes — v1.6 Draft 5.3.5

Draft 5.3.5 is a completed standalone corrective development corpus and remains
permanently not frozen. It does not claim theorem, promotion, or release
authority.

## Corrected

- Explicit OCI entrypoints independently reach compile and verify wrappers.
- Effective sandbox records are generated from exact applied commands and
  separate requested, applied, and measured controls.
- Immutable policy decisions are resolved before execution and bound through
  signatures, witnesses, SQL gates, API results, and replay.
- OCI version output is measured; UID/GID zero is rejected.
- Source snapshotting is descriptor-relative, streamed, mutation-aware, and
  bounded by file, directory, byte, path, depth, entry, and time limits.
- Host and container subprocess output is capped while produced; process groups
  are terminated on quota or timeout.
- The Lean inspector has a dedicated Lake executable and reproducible-build
  protocol; real build evidence remains pending.
- Every schema is lifecycle-classified and every canonical schema has positive
  and negative coverage under strict AJV.
- OpenAPI and the WSGI adapter implement one synchronous, idempotent route.
- Recursive inventory exclusions are explicit, and final-byte validation checks
  every stable size and digest.
- Source provenance is recorded truthfully as `unpublished_workspace`; this is
  an activation blocker rather than a fabricated commit identity.

## Activation blockers retained

Strict Lean, strict TLC, governed-image execution and runtime inspection, two
matching inspector/image build attestations, clean committed-source provenance,
and an external governance signature are absent unless separately supplied and
verified. The portable corpus cannot pass those gates on their behalf.
