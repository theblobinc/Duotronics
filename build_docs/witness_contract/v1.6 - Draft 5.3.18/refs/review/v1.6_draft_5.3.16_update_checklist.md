# Duotronics v1.6 — Draft 5.3.16 Update Checklist

## P0 — Authenticate publisher and anchor callers

### 1. Enforce Unix peer credentials

For every accepted connection:

- read `SO_PEERCRED`;
- compare UID/GID against an operation-specific allowlist;
- record PID and start-time identity where available;
- reject unknown peers before parsing or dispatching a mutation.

Required policy:

- proof-service UID may publish;
- publisher UID may mutate the anchor;
- no other UID may mutate either service;
- root is not implicitly trusted unless explicitly governed.

### 2. Harden socket configuration

Require exact:

- owner;
- group;
- mode;
- inode type;
- no-follow ancestry;
- parent mode and owner.

Reject world-writable publisher or anchor sockets.

### 3. Authenticate requests cryptographically

Add a canonical signed or MAC-protected request envelope binding:

- operation;
- request ID;
- peer principal;
- event or state digest;
- deadline;
- nonce or sequence;
- target service and socket identity.

## P1 — Enforce audit-key lifecycle everywhere

### 4. Strengthen registry validation

- reject rotation cycles;
- require predecessor chronology;
- preserve principal and scope across rotation where policy requires it;
- require one governed active key per operational role;
- distinguish record, receipt, checkpoint, recovery, and anchor scopes.

### 5. Recompute validity per signed artifact

For records, receipts, checkpoints, seals, recovery evidence, and anchor states:

- resolve the exact registry snapshot;
- reconstruct validity evidence;
- evaluate at the artifact timestamp;
- reject expired and revoked keys;
- apply documented historical-retirement rules.

Do not trust a self-contained decision string without recomputation.

## P2 — Make anchor transitions strict

### 6. Enforce exact same-segment transitions

Allow only:

- an exact idempotent no-op; or
- `new.sequence == current.sequence + 1`.

Keep immutable:

- namespace;
- epoch;
- segment ID;
- registry hashes;
- transition authorization;
- previous sealed-segment tail.

Bind every anchor state to the prior anchor-state SHAKE256-512.

### 7. Use a real monotonic activation anchor

Treat the file-backed store as development-only unless backed by:

- TPM/HSM monotonic state;
- WORM/object-lock storage;
- remote transparency service;
- independent quorum or root-owned monotonic helper with rollback detection.

## P3 — Verify segment succession completely

### 8. Verify the actual terminal record

Require:

- canonical terminal-record SHAKE256-512 equals checkpoint tail;
- canonical terminal-record SHAKE256-512 equals anchor tail;
- outer terminal segment equals predecessor segment;
- embedded seal segment equals predecessor segment;
- sequence and previous-record hash match the predecessor;
- event, record, checkpoint, anchor, and transition registry bindings agree.

## P4 — Global event idempotency

### 9. Carry event IDs across segment rotation

Maintain a publisher-domain global event-ID commitment or index.

A repeated canonical event must return `already_committed` even when:

- the original segment has been sealed;
- a successor segment is active;
- the publisher restarted;
- the client timed out before receiving the original receipt.

## P5 — Govern recovery authorization

### 10. Enforce authorization lifetime and one-time use

- require `created_at <= now < expires_at`;
- impose a maximum authorization lifetime;
- maintain a consumed-authorization ledger;
- reject replay;
- bind exact before-state and file identities;
- bind operator/governance principal and reason.

### 11. Reconcile schema and implementation

Implement and test every allowed recovery action or remove unsupported actions from the schema.

## P6 — Complete production audit services

### 12. Add production anchor launcher

Include:

- canonical config;
- governed anchor key registry;
- key validity selection;
- UID/GID drop;
- private socket;
- startup verification;
- signal handling;
- ledger rotation and recovery.

### 13. Add production publisher launcher

Include:

- audit key loading and lifecycle checks;
- segment selection and transition verification;
- anchor client setup;
- peer authentication;
- receipt-key policy;
- graceful shutdown and recovery.

### 14. Run a real three-service integration

Execute:

```text
proof service UID 65534
    → publisher UID 65533
        → privileged anchor service
```

Prove:

- valid publication;
- signed receipt;
- durable record and checkpoint;
- anchor advancement;
- restart replay;
- duplicate retry reconciliation;
- denied unrelated UID;
- key rotation;
- segment rotation;
- recovery authorization expiry.

## P7 — Low-level durability

### 15. Complete-write loops

Use bounded loops for every `os.write()`.

### 16. Anchor ledger lifecycle

Add:

- predecessor-state hash;
- segmenting or governed rotation;
- retention/compaction rules;
- ENOSPC and partial-write tests;
- rollback-detection evidence.

## P8 — Preserve portable validation

### 17. Continue Python 3.13 validation

Require:

- 303+ normal tests;
- warnings-as-errors;
- complete validator;
- zero surviving descendants;
- fresh extraction;
- exact regeneration.

Add Python 3.12 only when a current-revision interpreter is actually available.

## P9 — External activation gates

Complete independently:

1. strict Lean;
2. strict TLC;
3. governed hermetic Lean image;
4. signed OCI image build attestation;
5. signed verifier executable attestation;
6. reproducible inspector build attestation;

8. external governance authorization.

## Draft 5.3.16 acceptance criteria

- Revoked or expired audit keys cannot sign or replay records or receipts.
- Registry rotation cycles fail.
- Unauthorized local UIDs cannot invoke publisher or anchor mutations.
- Same-sequence anchor rewrites fail.
- File-anchor rollback is externally detected or the implementation is explicitly non-authoritative.
- Successors verify the actual anchored terminal record.
- Event idempotency survives segment rotation.
- Expired and replayed recovery authorizations fail.
- Production publisher and anchor launchers exist.
- A real cross-UID publication round trip passes.
- Authority remains disabled until all eight external gates complete.
