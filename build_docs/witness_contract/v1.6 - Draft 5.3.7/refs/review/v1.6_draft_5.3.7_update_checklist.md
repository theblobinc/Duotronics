   - `untrusted_compilation` → `compiler_artifact_file_size_limit`

4. Fail closed when the required domain-specific field is absent, malformed, Boolean, negative, zero when disallowed, or above the governed deployment maximum.


9. Bind the selected effective limit into:

   - the effective sandbox invocation;

   - invocation digest;
   - trusted runtime-control result;
   - verifier result;
   - compiler witness;
   - replay metadata.

# 4. Correct control-state semantics

**Priority:** Required assurance-model fix  
**Affected area:** effective sandbox invocation and runtime control evidence.

## Current issue

The invocation constructor initializes:

- `requested_controls`
- `emitted_controls`
- `accepted_controls`
- `applied_controls`

from the same configured set before runtime execution.

This overstates what is known before the OCI runtime has accepted or applied anything.

## Required changes

1. Define the control states precisely:

   - **requested:** required by policy or profile;
   - **emitted:** represented in the normalized OCI argv/configuration;
   - **accepted:** runtime accepted the configuration without rejection;
   - **applied:** runtime evidence indicates the control took effect;
   - **measured:** trusted inspection directly observed the resulting state;
   - **derived:** inferred from sealed execution topology rather than directly observed.

2. At invocation construction:

   - populate `requested_controls`;
   - derive `emitted_controls` from the generated argv;
   - leave `accepted_controls` empty;
   - leave `applied_controls` empty;
   - leave `measured_controls` empty.

3. Populate `accepted_controls` only after successful runtime creation/start and only for controls whose acceptance can actually be established.

4. Populate `applied_controls` only from runtime or platform evidence.

5. Populate `measured_controls` only from trusted in-container or host-side measurement.

6. Place topology-based properties such as result-channel isolation in `derived_controls` with the evidence root used to derive them.

7. Never copy requested controls into accepted, applied, or measured sets.

8. Require the final authority gate to use the appropriate evidence class for each control.

9. Document which controls are:

   - directly measured;
   - runtime-confirmed;
   - structurally derived;
   - impossible to verify on a given platform.

10. Add platform profiles so AppArmor, SELinux, seccomp, namespaces, and other controls are evaluated according to actual platform support.

## Required tests

- `test_preexecution_invocation_has_no_accepted_controls`
- `test_preexecution_invocation_has_no_applied_controls`
- `test_requested_controls_are_not_treated_as_evidence`
- `test_emitted_controls_are_derived_from_exact_argv`
- `test_measured_controls_require_observation`
- `test_derived_controls_include_evidence_root`
- `test_missing_control_evidence_fails_authority_gate`
