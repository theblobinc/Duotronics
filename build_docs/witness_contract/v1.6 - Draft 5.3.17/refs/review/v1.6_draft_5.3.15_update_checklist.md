# Duotronics v1.6 — Draft 5.3.15 Update Checklist

## P0 — Real rollback resistance

### 1. Add an independently monotonic audit anchor

The expected segment, sequence, and tail must be stored in a trust domain the proof service cannot roll back together with the log.

Acceptable deployment shapes include:

- remote append-only transparency service;
- WORM/object-lock storage;
- TPM/HSM monotonic state;
- root-owned checkpoint helper with a narrow append/update protocol.

Add tests for coordinated restoration of both the log and checkpoint.

### 2. Govern genesis and successor transitions

Successor provisioning must verify:

- predecessor sealed checkpoint;
- predecessor terminal seal record;
- terminal-record digest;
- signer authorization;
- governance-signed transition.

An arbitrary 64-hex predecessor value must not be enough.

## P1 — Rotation-capacity correctness

### 3. Reserve a terminal-seal slot and byte budget

Define separate limits for:

- normal audit events;
- terminal seal;
- total segment bytes.

Normal event appends must stop before consuming the reserved seal capacity.

Test:

- exact record boundary;
- exact byte boundary;
- seal-only segment;
- one byte below required seal capacity;
- concurrent seal and append.

### 4. Add governed recovery

Provide a repair command for:

- a fully signed log record with an older checkpoint;
- orphan checkpoint temporary files;
- interrupted segment seal;
- interrupted successor provisioning.

Every repair must produce signed recovery evidence.

## P2 — Honest deadline semantics

### 5. Hard-bound audit publication

Use a supervised audit worker or service so blocking fsync and storage operations can be terminated or isolated.

Bind an idempotent event identifier so an ambiguous timeout can be reconciled without duplicate records.

### 6. Stream verification

- `fstat` before read;
- reject oversized files before allocation;
- bounded chunked reads;
- deadline checks per chunk.

### 7. Clean failed checkpoint temporaries

Always remove uncommitted temporary files on failure.

## P3 — Audit authority governance

### 8. Add an audit signing registry

Include:

- key ID and principal;
- authorization scope;
- valid from/until;
- active/retired/revoked status;
- rotation predecessor;
- governance signature;
- historical verification keys.

Bind the registry digest and validity evidence into records, checkpoints, and seals.

## P4 — Path and storage policy

### 9. Enforce audit storage ancestry

Verify:

- complete no-follow ancestry;
- owner and mode;
- separate protection domain for the checkpoint;
- file and directory identities;
- replacement races.

Do not rely only on different immediate parent paths.

## P5 — Validator cancellation reliability

### 10. Handle external termination

Install SIGTERM/SIGINT handlers that terminate and reap:

- current phase worker group;
- escaped descendants;
- nested regression children.

Add tests that externally terminate the validator during:

- normal regression suite;
- warning-free suite;
- intentional escaped-descendant phase.

## P6 — Production and activation

### 11. Run the production non-root loader harness

Use a real multi-UID environment with the required procfs/fd-anchored SQLite support.

### 12. Complete the eight external gates

1. strict Lean;
2. strict TLC;
3. governed hermetic image execution;
4. signed OCI image build attestation;
5. signed verifier executable attestation;
6. reproducible inspector build attestation;
7. clean committed-source provenance;
8. external governance authorization.

## Draft 5.3.15 acceptance criteria

- Restoring an older matching log/checkpoint pair is detected.
- Successor segments prove a real sealed predecessor.
- A full segment can always append its terminal seal.
- Audit publication is hard-bounded or the documentation no longer claims it is.
- Oversized logs are rejected before full read.
- Failed checkpoint writes leave no temporary artifacts.
- Audit key lifecycle is governance-authorized.
- External validator termination leaves zero descendants.
- The real non-root production loader harness passes.
- Authority remains disabled until every external gate is independently complete.
