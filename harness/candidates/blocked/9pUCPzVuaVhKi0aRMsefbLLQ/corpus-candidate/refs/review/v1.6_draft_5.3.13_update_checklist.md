# Duotronics v1.6 — Draft 5.3.13 Update Checklist

## P0 — Complete historical cache-row verification

### 1. Bind historical rows to the current request before rotation classification

After envelope signature verification, require exact equality for:

- authenticated principal ID;
- idempotency key;
- canonical request SHAKE256-512;
- request ID;
- claim ID and claim-content hash;
- compiler profile;
- policy decision ID and hash;
- source bundle;
- proof artifact path;
- signed compiler-witness request bindings.

Only a correctly bound historical row may enter the rotation-specific path.

### 2. Enforce registry existence at signing time

Require:

```text
historical_registry.created_at <= cache_signed_at
```

Also validate:

- lineage creation is after all referenced registries;
- each predecessor registry predates its successor;
- signing-time evidence binds the registry creation timestamp.

### 3. Upgrade stale-row evidence

Add:

- authenticated principal ID;
- idempotency key;
- request SHAKE256-512;
- request ID;
- claim ID;
- compiler-witness signed-payload SHAKE256-512;
- cache signed-at;
- historical registry created-at;
- lineage created-at;
- exact binding-verification result.

Add adversarial fixtures for transplant, cross-principal replay, cross-request replay, and retroactive registry authorization.

### 4. Add a durable production evidence sink

The production loader must configure a real sink.

Requirements:

- append-only or tamper-evident storage;
- dedicated audit signing/MAC key;
- bounded record size and retention;
- durable write before returning the rotation `409`;
- stable error if evidence publication fails;
- startup verification and rotation policy.

## P1 — Run real production-loader integration

### 5. Execute the included harness in a multi-UID environment

Require a real pass showing:

- root-owned immutable `/` and `/etc`;
- service-owned private trust root;
- real `setgid`/`setuid`;
- both production loaders pass;
- root execution remains rejected;
- SQLite database and WAL/SHM ownership are correct;
- schemas, keys, and signed registries are loaded canonically.

Store passing evidence and make it required for an activation candidate.

## Draft 5.3.13 acceptance criteria

- Transplanted authentic historical envelopes are rejected as integrity failures.
- A registry cannot authorize a cache signature from before the registry existed.
- Stale-row evidence contains complete request and chronology bindings.
- Production stale evidence is durably and cryptographically recorded.
- The real non-root loader harness passes.
- Dual-Python validation remains clean and repeatable.
- Authority remains disabled until all eight external gates are complete.
