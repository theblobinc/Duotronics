# Duotronics v1.6 — Draft 5.3.11 Update Checklist

## P0 — Production-loader correctness

### 1. Fix trusted-root ancestry ownership rules

Replace the current “every component must equal the service UID” rule with a tiered policy.

Required behavior:

- `/` and immutable system ancestors may be UID 0.
- Every ancestor must be a real directory and not group/world writable.
- Symlinks are forbidden.
- The final private trust root must be owned by the configured service UID and use a private mode.
- Sensitive descendants must be owned by the governed service UID.
- Public immutable artifacts may use an explicitly governed root-owned policy.

Required tests:

- non-root service with `/etc/witness-authority`-style layout succeeds;
- root service remains rejected;
- wrong owner, writable ancestor, symlink, hard-link ambiguity, and replacement races fail;
- `load_production_authority_service()` and `load_production_application()` both run through real non-root trust-root loading.

## P1 — Cache-key chronology

### 2. Enforce `status_changed_at`

- Reject timestamps in the future.
- Define valid chronology for active, retired, and revoked states.
- Require status-change time to be coherent with `valid_from` and `valid_until`.
- Include status-change time in validity evidence.
- Recheck chronology during replay.

Required tests:

- future active status rejected;
- future retired/revoked status rejected;
- status change outside the validity interval rejected;
- valid rotation chronology accepted.

### 3. Define stale cache-row recovery

Choose and document one behavior after key rotation or registry replacement:

- quarantine/delete and safely re-execute; or
- reject with a stable error requiring a new idempotency key.

Record tamper/rotation evidence before removing any row.

## P2 — Canonical trusted inputs

### 4. Use canonical duplicate-rejecting JSON loading

Apply to:

- service configuration;
- compiler registry;
- proof-policy registry;
- trusted-artifact registry;
- platform capability evidence;
- cache-signing registry;
- authority schema documents where applicable.

Require:

- duplicate-free objects;
- canonical re-encoding equality where the format is declared canonical;
- schema validation;
- signature or trusted-artifact verification after canonical parsing.

Add adversarial tests for duplicate keys, alternate whitespace/order where canonical bytes are required, and noncanonical numeric/string encodings.

## P3 — Python matrix assembly

### 5. Replace the hard-coded unavailable-version generator

- Generate one evidence record per interpreter.
- Merge existing validated records rather than overwriting them.
- Remove the current version from unavailable versions.
- Require validated and unavailable sets to be disjoint.
- Require every target major/minor exactly once.
- Make the combined matrix deterministic and hash-covered.

### 6. Validate on both Python lines

Run, from separate clean extractions:

- Python 3.12 normal suite;
- Python 3.12 warnings-as-errors;
- Python 3.12 full validator;
- Python 3.13 normal suite;
- Python 3.13 warnings-as-errors;
- Python 3.13 full validator.

The assembled matrix must preserve both exact patch-version records.

## Draft 5.3.11 acceptance criteria

- Non-root production loaders can read a secure standard Linux trust-root layout.
- Root execution remains forbidden.
- Future status-change timestamps are rejected.
- All trusted JSON is duplicate-free and canonical.
- Python 3.12 and 3.13 matrix records are complete, disjoint, and reproducible.
- The full validator passes on both Python lines.
- All eight external gates remain fail-closed unless independently verified.
