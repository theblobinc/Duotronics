# Duotronics v1.6 — Draft 5.3.14 Update Checklist

## P0 — Rollback-resistant audit evidence

### 1. Protect the audit tail outside the mutable log

Add a protected checkpoint containing:

- segment ID;
- sequence;
- tail-record SHAKE256-512;
- previous sealed-segment tail;
- audit signer key ID;
- checkpoint creation time;
- governance or external audit signature.

Production startup must compare the complete log tail with this checkpoint.

### 2. Reject rollback and deletion

Required failures:

- valid-prefix truncation;
- complete audit-file deletion;
- replacement with an older valid segment;
- replacement by an empty file;
- competing genesis creation;
- unsealed segment transition.

Do not use `O_CREAT` during normal startup for an already provisioned production segment.

### 3. Define governed segment rotation

- terminal signed seal record;
- successor segment binds predecessor tail;
- maximum bytes and records;
- externally persisted checkpoint update;
- crash-safe rotation protocol;
- no overwrite or silent reset.

## P1 — Deadline-bound audit publication

### 4. Pass the request deadline into cache verification and the audit sink

- `_cached_result(..., deadline_monotonic)`
- `_publish_cache_evidence(..., deadline_monotonic)`
- `SignedAppendOnlyAuditSink(..., deadline_monotonic)`

### 5. Bound every audit operation

- nonblocking lock attempts with remaining-time retries;
- deadline checks after chain verification;
- deadline check before append;
- deadline check after file fsync;
- deadline check after directory fsync;
- stable timeout or `cache_audit_publication_failed` response.

Add slow-lock and slow-fsync regressions.

- Normal production startup cannot silently create a new audit genesis.
